> 命令以仓库根目录为当前目录，`.venv` 为本地虚拟环境。

## 1. 页面核闸口：缺印批不能放行

1. 底栏点 **闸口**。
2. **闸口目录**：应显示门槛芯片 `门槛 qi-check-downstream v1 · qi-check-downstream@1#aa23b829d3ff4631`，
   下方“只读历史门槛”列出 `legacy-silent-release v0`。
3. **印记值卡片**：三个待盖印批次整行浅红，印记值列显示 `缺印` 红标。
4. **下游表附页**：`gmv-20261114-01` 齐检列显示红标 `缺印`，缺印列列出 `gmv/ord-14/pay-14`。
5. **放行进度**：空列表，无任何放行行。
6. 点 `gmv-20261114-01` 行的 **放行** 按钮 → 顶部提示红字
   **`本批 gmv-20261114-01 缺印，禁止放行`**，列表不变。

命令行等价核验：

```bash
curl -s -c /tmp/wm.cj -X POST http://127.0.0.1:7711/api/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"123456"}'
curl -s -b /tmp/wm.cj -w '\nHTTP %{http_code}\n' -X POST http://127.0.0.1:7711/api/release \
  -H 'Content-Type: application/json' -d '{"run_code":"gmv-20261114-01"}'
# 期望：HTTP 409，error 含“缺印”
```

**本机库可核**：此时库中不应存在放行行。

```bash
sqlite3 /tmp/wm-accept.db "SELECT COUNT(*) FROM release_records;"   # 期望 0
```

## 2. 补齐印记后放行成功，凭证落库

1. 页面 **批次** 页，依次给 `ord-20261114-01`、`pay-20261114-01`、`gmv-20261114-01` 盖印
   （任填印记值，如 `WM-SEED-1/2/3`）。
2. 回 **闸口** 页：印记值卡片红标消失；下游表附页齐检列变 `齐检齐备`，放行列 `未放行`。
3. 点 **放行** → 顶部提示 `放行完成 · 凭证 qi-check-downstream@1#…:…`；
   放行进度出现一行，带**门槛芯片**（含齐检凭证）。
4. 再点同一行放行按钮已消失；直接重复请求返回 `409 批次已放行`。

```bash
sqlite3 /tmp/wm-accept.db \
  "SELECT run_code, gate_id, gate_version, credential FROM release_records;"
# 期望：一行 gmv-20261114-01，credential 形如 qi-check-downstream@1#aa23b829d3ff4631:xxxxxxxxxxxxxxxx
```

## 3. 排他锁：两侧仓管同时抢放行只落一行

在 `ord-20261114-01` 尚未放行时并发两次（该批自身已齐检）：

```bash
for i in 1 2; do
  curl -s -b /tmp/wm.cj -X POST http://127.0.0.1:7711/api/release \
    -H 'Content-Type: application/json' -d '{"run_code":"ord-20261114-01"}' \
    -w ' HTTP %{http_code}\n' &
done; wait
```

期望：一次 `HTTP 200`，一次 `HTTP 409 批次已放行`。

```bash
sqlite3 /tmp/wm-accept.db \
  "SELECT COUNT(*) FROM release_records WHERE run_code='ord-20261114-01';"   # 期望 1
```

自动化覆盖：`tests/test_release_gate.py::test_concurrent_release_single_write`。

## 4. 顺藤复验：缺印已放行记录不得再被读到

1. 上面已放行 `gmv-20261114-01`。
2. 手工把一段上游印记抹掉，制造“缺印已放行”脏记录：

```bash
sqlite3 /tmp/wm-accept.db \
  "UPDATE run_batches SET status='待盖印', watermark_value=NULL WHERE run_code='pay-20261114-01';"
```

3. 页面 **追索**，水印值填 `WM-SEED-1` 点追索：
   下游列表**不再出现** `gmv-20261114-01`，改出现红条
   **`复验拦下 1 条缺印放行记录：gmv-20261114-01`**。
4. 回 **闸口** 页：放行进度顶部出现
   **`齐印与可放行不同源，已自动停止放行，请核查。`**，
   已放行的 `gmv-20261114-01` 行显示红点 + 缺印行底色。
5. 此时任何新的放行动作都被整体拦住：

```bash
curl -s -b /tmp/wm.cj -w '\nHTTP %{http_code}\n' -X POST http://127.0.0.1:7711/api/release \
  -H 'Content-Type: application/json' -d '{"run_code":"pay-20261114-01"}'
# 期望：HTTP 503 “检测到缺印已放行（gmv-20261114-01），已停止放行”
```

自动化覆盖：`tests/test_release_gate.py::test_trace_withholds_missing_stamp_release`、
`test_missing_stamp_already_released_stops_all`。

## 5. 只读历史门槛：旧门槛已迁出且不可改

```bash
sqlite3 /tmp/wm-accept.db "SELECT run_code, reason FROM legacy_release_history;"
sqlite3 /tmp/wm-accept.db "UPDATE legacy_release_history SET reason='x';"
# 期望：ERROR ... 只读历史：禁止修改

ls -l app/gates/qi_check_gate.json app/gates/history/legacy_silent_release.json
# 期望：权限为 -r--r--r--（不可写）
```

改动门槛文件即停止放行（自动化覆盖：`test_tampered_gate_file_stops_release`）：

```bash
printf ' ' >> app/gates/qi_check_gate.json   # 若权限已只读会失败，可用 chmod u+w 后追加
curl -s -b /tmp/wm.cj -w '\nHTTP %{http_code}\n' -X POST http://127.0.0.1:7711/api/release \
  -H 'Content-Type: application/json' -d '{"run_code":"gmv-20261114-01"}'
# 期望：HTTP 503 “齐检门槛文件被改动，已停止放行”
git checkout -- app/gates/qi_check_gate.json   # 验收后复原
```

## 6. 只改文案 / 只改色块不算通过

验收必须同时看到：**拒绝入库（409/503 且有中文短句）**、
**本机库无缺印放行行**、**页面四处一致**。
仅修改 `static/` 文案或放行进度色块不触发以上任一后端行为，判为失败。
